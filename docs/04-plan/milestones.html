Milestones

Seven milestones from an empty Xcode project to an outside TestFlight build.

One-sentence version

Seven milestones run from card data and decks, through a fully-playable-by-hand sandbox, through the rules engine and AI, to a friend installing the app from TestFlight.

Sequencing rationale

Why M2 comes before any rules subsystem

M2 is deliberately front-loaded so that something fully playable exists before any rules subsystem is written. It also de-risks C1 — if the rules-engine scope proves too large, M2 alone is already a usable manual deck-testing sandbox, and Simple Bot Mode (the road not taken) becomes the fallback for M5.

Every [PROPOSED] decision is parked behind the milestone that would prove it right or wrong.

Per-milestone detail

M1 — Foundations, Card Data & Decks

T0 · Size M · Depends on: nothing

Definition of done: Paste a 100-card Commander decklist, and within 30 seconds every resolvable card shows its correct name, mana cost, type line and cached image in the deck detail view, with unresolved names listed separately and retryable. App relaunches offline and the deck still renders fully.

Includes: Xcode project + folder conventions · CardDefinition model · Scryfall bulk-data ingest + per-card fallback · image cache · SwiftData persistence · decklist text parser · deck library + deck detail views · unresolved-card handling.

Services: GitHub (T0), Scryfall (T0), Linear (T0), Cloudflare Pages for docs (T0).

M2 — Game State & Manual Play Sandbox

T0 · Size L · Depends on: M1

Definition of done: Start a 2-player Commander game from the setup screen, mulligan, and play a complete game to a natural finish entirely by hand — draw, play lands, cast by moving cards to the stack and resolving them yourself, tap/untap, add counters, create tokens, move any card to any zone, change life totals — without the app ever blocking a legal or illegal action. Closing and reopening the app resumes the game exactly.

Includes: Game/Player/Zone/GameCard/GameAction/Turn/CardLayout models · seeded RNG · zone manager · game setup screen · freeform battlefield with drag/z-order/spawn rules · opponent panels · tap/untap · counter & damage badges · card status display · enlarged card view with counters and Move Zone · Ordered Zone Viewer + shared search · exile tags · command zone UI · manual token picker + creation pipeline · token grouping · attachments rendering · mulligans · manual turn/phase advancement · active turn indicator · reversible-action architecture (architecture only).

M3 — Rules Core

T0 · Size L · Depends on: M2

Definition of done: The engine independently drives a game — you cast a spell and the engine handles priority, puts it on the stack, detects and orders triggers, checks SBAs to fixpoint, applies replacement effects, recomputes layered characteristics, and computes legal mana payments — with Developer Mode showing the full layer evaluation for any permanent.

Includes: Decision pipeline (DecisionRequest/DecisionResponse) · priority · stack resolution · trigger detection, optional-trigger prompts, APNAP ordering · SBAs · replacement & prevention · continuous effects layer system · mana system + floating-mana UI · targeting + restrictions · Developer Mode overrides and layer inspector.

M4 — Combat & Copy Effects

T0 · Size M · Depends on: M3

Definition of done: Declare attackers and blockers in a real game; the engine enforces every restriction and requirement, assigns damage per official rules, prompts only for blocker order and trample, and Developer Mode shows the complete combat state including first/double strike. Copying a spell produces an independent stack object and prompts for new targets.

Includes: combat sequence · attack/block legality · damage assignment · combat state exposure · copy effects.

M5 — AI Opponent

T0 · Size M · Depends on: M3

Definition of done: A bot takes a complete turn against you — untaps, draws, plays a land, casts spells, attacks — answering every engine DecisionRequest through the AIEngine pipeline, never touching state directly, and producing byte-identical play when replayed from the same seed.

Includes: AI Interface · Game Knowledge View · Action Generator · Action Evaluator · Decision Selector · strategy-based difficulty scaffold · deterministic AI randomness.

M6 — History, Persistence & Replay

T0 · Size M · Depends on: M2 (architecture), M4

Definition of done: Undo walks back at least ten consecutive actions correctly, redo restores them until a new action clears the redo stack, a saved game reloads to an identical state, and a replay of a finished game steps forward and backward through every action producing the same board at every point.

Includes: multi-step undo · redo · game serialization · replay engine with play/pause/step · Developer Mode historical state inspection.

M7 — Ship to a Tester

T1 · Size S · Depends on: M4, M5, M6

Definition of done: A person who is not you installs the app from TestFlight, imports their own deck, plays a game against a bot, and a crash they hit appears in your error tracker with a usable stack trace.

Includes: Apple Developer Program enrollment · TestFlight build + release notes · Sentry integration · onboarding/first-run pass · crash-free smoke test on a second physical device.
