Content extracted from diagrams

Searchable transcription of S5–S8. The reconciled design is in architecture overview and data model.

Top-level component decomposition (0.1 - CD)

App → Views, ViewModels, Models, Engines, Database, CardAPI.

Engines contains GameEngine, AIEngine (and, in S6/S8 only, a sibling RulesEngine).

Database contains Database API, Storage.

0.1.2 - EnginesCD — engine interaction contract

  • App → GameEngine: Human actions
  • GameEngine → AIEngine: Decision request, permitted game state
  • AIEngine → GameEngine: chosen action or response
  • GameEngine → App: State + decision requests
  • GameEngine ↔ Database: Card data + save/load

0.1.2.1 - GameEngineCD — GameEngine internals (6 subsystems)

SubsystemStated responsibility
Engine InterfaceEntry and exit point for engine
Game Flow CoordinatorControls what happens next
Action ProcessorValidates and processes intents
Rules SystemProvides rules knowledge
History SystemStores history of actions
Game State StoreOwns state of the game

0.1.2.2 - AIEngineCD — AIEngine internals (5 subsystems, pipeline)

AI Interface (entry/exit) → Game Knowledge View (builds context; receives permitted game information) → Action Generator (generates legal candidate actions) → Action Evaluator (scores how useful each action is) → Decision Selector (chooses from scored candidates) → returns Selected Response.

0.2.x CRDs — field-level data model

The only field-level source that exists. Reproduced verbatim, including its two unresolved types.

Game
  - gameId: UUID
  - randomSeed: ?          <-- type unresolved in source
  - timestamps: Time
  - players: UUID
  - turnNumber: Int
  - currentTurn: Turn
  - actionHistory
  + Game(players: List)
  + passTurn(): Turn

GameCard
  - cardDefinitionID: UUID
  - id: UUID
  - owner: UUID
  - controller: UUID
  - currentZone: ref
  - isVisible: Bool
  - isToken: Bool
  - basePowerToughness: PowerToughness
  - ptModifiers: [String: PowerToughness]
  - ptCurrent: PowerToughness
  - isTapped: Bool
  - isSummoningSick: Bool
  - attachments: List
  - counters: map
  - transitionHistory: List

Player
  - id: UUID
  - isUser: Bool
  - userID?: UUID
  - startingLife: Int
  - currentLife: Int
  - manaPool: ?            <-- type unresolved in source
  - counters: map
  - zones: List
  - deck: Deck
  - timesCommandCast: Int

Zone
  - type: ZoneType
  - id: UUID
  - cards: List<ref>

GameAction
  - id: UUID
  - actionSequenceNumber: Int
  - playerID: UUID
  - actionType: ActionType

CardDefinition
  - "found from scryfall API"   <-- no fields enumerated

CardLayout  (from S2 prose, not diagrammed with fields)
  - gameCardId, xPosition, yPosition, zIndex

enum ZoneType   = LIBRARY, HAND, BATTLEFIELD, … ("etc")
enum ActionType = SIMPLE, COMPLEX
enum CounterType = PLUS_ONE_PLUS_ONE, POISON, OIL, … ("etc")
