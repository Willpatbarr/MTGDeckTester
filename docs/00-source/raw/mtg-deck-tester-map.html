MTG Deck Tester — top level

The core layering from the spec: Views → DeckStore / GameEngine / BotEngine → Models. UI sub-areas and engine internals live in their own diagrams; only the major zones are shown here.

GameEngine — rules core

Featured: the rules engine and its subsystems (§2–§3). Humans and bots both act through the Decision Pipeline; the engine never lets the UI infer rules state. Combat, layers and mana are summarized here — deeper splits are candidates for /archmap add.

Battlefield UI

Featured: the battlefield play surface (§5). Human field is freeform drag-and-drop; opponents use compact managed panels. Layout is UI-only and excluded from replay determinism.

Enlarged Card View

Featured: the persistent modal opened by long-pressing a battlefield card (§4). Supports inspection, counter edits and zone moves; it deliberately forbids tap/drag/attach. Stays open across zone changes until explicitly dismissed.

Zones, Search & Inspection

Featured: the shared Ordered Zone Viewer and search system (§4). One viewer, configured per zone, is reused for libraries, hands, graveyards, exile, stack and the token picker. MVP search is text-only; hidden zones are fully inspectable for testing clarity.

Tokens

Featured: token behavior and creation (§6). Tokens are GameCards with isToken = true and behave exactly like permanents; grouping is a purely visual arrangement. Manual and automatic creation share one engine pipeline.

History, Persistence & AI

Featured: the deterministic-action features (§7). Ordered, reversible GameActions power undo/redo, save/load and deterministic replay. The AI (BotEngine) plans through the same DecisionRequest pipeline as humans and never mutates state directly.

Data Model

Featured: the model entities from §2 as a class diagram (simplified UML — inheritance vertical, has-a horizontal; composition = filled diamond, aggregation = open, association = open arrow). GameCard is the hub; GameAction specializes into Simple/Complex actions.
