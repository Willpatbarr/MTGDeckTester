Deploy

Deployment paths for the docs site and app. The app path is not active yet.

One-sentence version

There are two entirely independent deploy paths — docs go live automatically about a minute after a commit to main, while the app path through TestFlight is fully specified but does not exist yet.

Two unrelated paths

The docs path and the app path share no infrastructure, no trigger, and no timing. Deploying docs never touches the app, and there is currently no way to trigger the app path at all — see the callout under App.

1. Docs

Commit to main. The docs site rebuilds automatically from the docs/ folder and is live in about a minute. No build step, no manual publish action.

OptionConfigNote
GitHub PagesServe from branch main, folder /docsPages on a private repo requires a paid GitHub plan. See github.html.
Cloudflare Pages (documented fallback)Build command: none · Output directory: docsFree on a private repo. See cloudflare-pages.html.

2. App

Does not exist yet

The app path is gated behind the Apple Developer Program, a T1 service (see apple-developer.html) that is not enrolled in today. Stated plainly: there is currently no way to ship this app to anyone. This section describes the path as designed, to be executed at milestone M7.

  1. Xcode › Product › Archive.
  2. Organizer › Distribute App › TestFlight & App Store.
  3. Apple processes the build. This typically takes 5–30 minutes.
  4. Testers receive the new build through the TestFlight app on their own device.

What to do next

  1. For docs changes: just commit to main and check the site in about a minute.
  2. For the app path: nothing to do until M7 — enroll in the Apple Developer Program first (see apple-developer.html).
  3. If you're setting this up for the first time, confirm which hosting option (GitHub Pages vs. Cloudflare Pages) is actually configured in 03-services before assuming either is live.
