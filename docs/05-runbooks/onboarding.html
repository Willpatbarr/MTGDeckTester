Six architectural principles

From 02-architecture/overview.html §5.1, restated compactly. Code that violates these should be treated as a bug, not a style preference.

  1. Strict engine, permissive UI. The engine is rules-accurate. The UI is a testing tool: it shows all hands and libraries, offers every zone destination, and never blocks you.
  2. The UI never infers rules state. Attackers, blockers, attachments, layers, and legality are explicit GameEngine state, read by the UI, never derived in it.
  3. One decision pipeline. Humans and AI answer the same DecisionRequest. The AI never mutates state directly.
  4. Determinism is load-bearing. Every random choice goes through the game's seeded generator. Replay must be exact.
  5. Layout is not game state. Moving a card within a zone is a layout operation — no GameAction, not undoable, excluded from replay.
  6. Rules knowledge is a subsystem, not a service. No RulesEngine type exists; rules live inside GameEngine.
