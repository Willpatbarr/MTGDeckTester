Local Setup

Fresh clone to a running simulator, with troubleshooting.

Not real yet

No Swift code exists in this repo today — the Xcode project itself is M1 work. This runbook describes the setup as designed. It becomes literally accurate the moment M1 lands; until then, treat it as the target.

One-sentence version

Clone the repo, open it in Xcode, sign it with your own free Apple ID, set one environment variable, and let the first launch download the Scryfall card database before you test with the sample decklist.

Prerequisites

  • A Mac running a recent macOS release.
  • The current stable release of Xcode, installed from the App Store.
  • An Apple ID. A free personal Apple ID is enough — this is the T0 path. The paid Apple Developer Program is not needed for local development; see deploy.html and apple-developer.html for when it becomes required.
  • A stable internet connection for the first launch (the Scryfall bulk download, see step 6).

Clone to running

  1. Clone the repo.

    git clone https://github.com/Willpatbarr/MTGDeckTester.git
  2. Open the project. Open MTGDeckTester.xcodeproj (or the workspace, once M1 establishes the project) in Xcode.
  3. Set your own Team. In the project settings, go to Signing & Capabilities and pick your own Apple ID under Team. Xcode will generate a personal signing certificate automatically — no paid account required at this stage.
  4. Set the Scryfall user agent. Edit the run scheme (Product › Scheme › Edit Scheme › Run › Arguments › Environment Variables) and add SCRYFALL_USER_AGENT with a descriptive value, e.g. MTGDeckTester/0.1 (your-contact-info). Scryfall asks for this on every request — see scryfall.html.
  5. Build and run on the simulator. Pick any iPhone simulator target and run.
  6. Wait through the first-launch download.
    This takes a while

    On first launch the app downloads Scryfall's default_cards bulk data file and parses it into local storage. Decompressed, this is roughly 150 MB. On a slow connection this can take several minutes — let it finish before assuming something is broken.

Folder layout, once M1 creates it

The agreed convention (see conventions.html) so the project doesn't drift while it's being built out:

FolderHolds
Models/CardDefinition, GameCard, Player, Zone, Game, GameAction, and the rest of the data model.
Views/SwiftUI views — battlefield, enlarged card, ordered zone viewer, tokens, command zone.
ViewModels/Observable state adapters. No rules logic lives here.
Engines/GameEngine/Engine Interface, Game Flow Coordinator, Action Processor, Rules System, History System, Game State Store.
Engines/AIEngine/AI Interface, Game Knowledge View, Action Generator, Action Evaluator, Decision Selector.
Database/Database API and Storage — decks, card cache, game saves.
CardAPI/Scryfall client and image cache.

Verification

Setup is confirmed working when this succeeds:

  1. Import the sample decklist checked into the repo.
  2. Open the deck detail view.
  3. Confirm every resolvable card renders with its correct name, mana cost, type line, and cached image.

Troubleshooting

SymptomCauseFix
Build fails with a signing errorNo Team selected in Signing & CapabilitiesSet your own Apple ID as the Team (step 3). A free Apple ID is enough; you do not need the paid Developer Program yet.
App hangs or crashes on first launchThe Scryfall bulk download was interrupted (network drop, app backgrounded, simulator killed)Relaunch. The ingest re-checks and resumes/restarts the bulk fetch rather than assuming a partial file is complete.
A card in your decklist never resolvesName mismatch against Scryfall, or a transient lookup failureThis is expected for some real decklists. It's handled by the unresolved-card retry flow (G6) — the card shows in a "needs attention" row in deck detail with a retry and a manual-search action.
