TelemetryDeck

What this is: privacy-first usage analytics, deliberately deferred until it's actually needed.  What to do with it: ignore this until the T2 trigger fires — do not integrate it early "just in case."

What & why

TelemetryDeck would answer "which features does anyone actually use" once there are enough testers that the answer isn't obvious from just talking to them. It reports aggregate, anonymized usage signals rather than individual user tracking.

Alternatives considered: Amplitude/Mixpanel (powerful, but heavyweight and explicitly rejected as premature per the services index — a privacy tax on a personal tool with zero users) and Firebase Analytics (drags in the Firebase SDK for one feature, same objection as Sentry's Crashlytics alternative). TelemetryDeck won for being privacy-first by default and lightweight, matching a solo tool that doesn't want to collect more than it needs.

Setup steps

Not applicable yet — this service is intentionally not set up. When the T2 trigger fires, the outline is:

  1. Create a TelemetryDeck account and a new app entry.
  2. Obtain the app ID / signal key from the TelemetryDeck dashboard.
  3. Add the TelemetryDeck Swift Package to the Xcode project.
  4. Initialize the SDK with the app ID, and decide which events are worth tracking — feature usage only, never personal or deck-content data.
  5. Confirm the SDK's default anonymization/opt-out behavior matches the project's privacy stance before shipping.
  6. Verification (when this is actually set up): trigger a test event from a debug build and confirm it appears in the TelemetryDeck dashboard within a few minutes.

Real secrets are never committed to the repository. Even though the app ID here is client-safe, it stays out of the codebase until the service is actually turned on — no placeholder wiring before it's needed.

Escape hatch

Lock-in: Low. Usage analytics are additive and non-authoritative — nothing in the app's core logic depends on TelemetryDeck data existing or being accurate.

Migrating off it means swapping the SDK initialization for another analytics provider (or removing analytics entirely) and updating the one config value. No historical data needs to be preserved for the app to keep functioning.
