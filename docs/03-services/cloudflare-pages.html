Cloudflare Pages

What this is: the host that turns docs/ into a live site on every push to main.  What to do with it: set it up once per the steps below; after that it's fire-and-forget.

What & why

Cloudflare Pages watches the GitHub repo and rebuilds a static site from the docs/ folder every time main changes, giving this planning documentation a real URL instead of living only as files in a private repo. There is no build step — it's plain HTML/CSS being served as-is.

Alternatives considered: GitHub Pages (works, but Pages on a private repo requires a paid GitHub plan — see github.html — so it's the documented fallback rather than the primary) and Netlify (functionally near-identical free tier, no reason to prefer it over Cloudflare here). Cloudflare Pages won because it serves private-repo static sites for free with generous bandwidth and no plan upgrade needed.

Setup steps

  1. Create or sign in to a Cloudflare account.
  2. Workers & Pages → Create application → Pages → Connect to Git.
  3. Authorize Cloudflare's GitHub App and select Willpatbarr/MTGDeckTester (a private repo — this is supported).
  4. Production branch: main. Build command: none (leave blank). Build output directory: docs.
  5. Deploy. Cloudflare assigns a default *.pages.dev subdomain automatically — no custom domain is required to get a working URL.
  6. Verification: visit the assigned *.pages.dev URL and confirm docs/index.html renders; then push a trivial commit to main and confirm the live site updates within about a minute.
Painful to change later

The output directory (docs) and production branch (main) are cheap to change in Cloudflare's dashboard, but a custom domain, once attached, involves DNS propagation delay to move. None of that is in play yet — the default *.pages.dev subdomain is sufficient for now.

Escape hatch

Lock-in: Low. The entire site is static HTML with a single shared stylesheet and a small nav script — no Cloudflare-specific templating or functions are used.

Migrating off Cloudflare Pages means pointing any other static host (GitHub Pages once paid, Netlify, or even caddy file-server run from the repo) at the same docs/ folder. It renders identically anywhere; this is a same-day change.
