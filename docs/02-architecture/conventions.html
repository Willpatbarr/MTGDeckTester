Conventions

What this is: the folder layout, naming rules, and hard engine constraints that keep the codebase consistent.  What to do with it: follow it every time you add a file or write engine code; the banned names exist because both mistakes already happened once in the source diagrams.

One-sentence version

Two names are banned, every state mutation is a GameAction, and randomness only ever comes from the game's seeded generator.

Engine rules

Every state mutation goes through a GameAction

If it doesn't change game state, it isn't a GameAction. This is what keeps the action history complete and makes undo, redo, save, load, and replay all work off the same list.

Every GameAction is reversible, or explicitly marked irreversible

Reversibility is designed in from the start of the model, per contradiction C9, even though the undo feature itself ships later.

No Bool flags on the engine for UI concerns

UI state belongs in ViewModels, not on engine types. If a flag exists only to change how something renders, it does not belong on the engine.

Randomness only via the game's seeded generator

Int.random(in:) is banned in engine code. Every random choice must draw from the game's SeededGenerator so that replay stays byte-identical — see Principle 4 in overview.html.

  1. Set up the folder layout above when the Xcode project is created.
