2. Resolved model

The additions and resolutions from the architecture brief, filling gaps G4 and G9.

randomSeed

randomSeed: UInt64. Games use SeededGenerator: RandomNumberGenerator. Every random choice in the engine — shuffles, AI randomness, anything — draws from this generator, which is what makes replay byte-identical. See Principle 4 in overview.html.

manaPool

manaPool: ManaPool = [ManaSymbol: Int] plus an ordered list of restricted mana objects. A plain dictionary of counts is not enough: mana with a "spend only on..." rider needs its own identity, not just a tally, so restricted mana is tracked as an ordered list of individually addressable objects alongside the count-based pool for unrestricted mana.

CounterStack

Shared by cards and players: type: CounterType, amount: Int. Created on first add, removed at zero.

ZoneTransition

Records every zone move. Retains exile tags after they are cleared from the exile UI, so transition history stays complete even once a tag is no longer shown.

Boundary that matters

CardLayout is UI-only. It is excluded from rules processing and from replay determinism. Moving a card within a zone is a layout operation, not a rules operation, and produces no GameAction — see Principle 5 in overview.html.

What to do next

  1. Build models from section 2, not section 1 — section 1 is kept only as the historical record.
  2. When adding a new CardDefinition field, check whether it changes rules behavior; if so it likely belongs in the Rules System, not just the model.
  3. Read conventions.html for the rule that every state mutation must go through a GameAction — this is what keeps CardLayout correctly excluded.
